# STM32C5 support for Kalico and Katapult: design

Date: 2026-10-01. Status: approved in conversation section by section; this document awaits Erik's review.

## 1. Goal

Run Kalico firmware and the Katapult bootloader on ST's STM32C551 and STM32C552 (STM32C55xxx: Arm Cortex-M33 with FPU, 144 MHz, 256 or 512 KB dual-bank flash, 128 KB SRAM). The first target is Erik's own STM32C552 board, which talks to the host over FDCAN, USB and UART and drives steppers (TMC over UART/SPI) and sensors. The code stays in Erik's forks (`erikbuild/kalico`, `erikbuild/katapult`); upstream pull requests are not a goal.

Work happens on branch `stm32c5-support` in both repositories (`~/Code/kalico`, `~/Code/katapult`).

## 2. Decisions

| Topic | Decision |
|---|---|
| Approach | Standalone `MACH_STM32C5` family. Kalico's draft H5 PR #348, Zephyr's C5 port and the hardware-validated H503 Klipper port (packerlschupfer/coreone-firmware) are cross-references only. No shared "H5-class" layer. |
| Parts | STM32C551 and STM32C552, either flash size, any package. Two Kconfig entries; `FLASH_SIZE` is the line's smallest part (256 KB), per Kalico convention. |
| `CONFIG_MCU` | `stm32c551xx` / `stm32c552xx`, identical in both repos (Katapult's flashtool refuses a mismatch). |
| Clock | SYSCLK 144 MHz from an 8, 16 or 24 MHz HSE crystal through PSI, or from the internal HSI144. 12/20/25 MHz clock references are hidden for C5; 32/48 MHz are not offered. Erik picks the board crystal from 8/16/24 MHz. |
| Float ABI | Soft-float, like every other Kalico ARM target. |
| Vendor headers | ST `STMicroelectronics/stm32c5xx-dfp` tag 2.1.0 (BSD-3-Clause), headers only; ST's `system_stm32c5xx.c` is not built (G0 precedent). |
| Build environment | Kalico's existing CI image `scripts/Dockerfile-build`, built locally as `kalico-build` for `linux/amd64`, plus a `scripts/docker-run.sh` wrapper. No toolchain on the Mac. |
| Debug probe | Erik has a J-Link / CMSIS-DAP probe for bring-up and verification. |
| Merge gate | Build tests, pytest and codex review. Hardware acceptance (section 9) is follow-up work once the board exists. |
| Reference material | `digest-docs/st/` (datasheet DS14928, RM0522, AN2606, ES0661) and the digests in `digest-docs/digest/st/` (index: `RM0522/README.md`). Research notes: `specs/research/`. |

## 3. Scope

In scope, in both repos where the item applies:

- Clock tree at 144 MHz (section 5.3), USB 48 MHz clock, FDCAN and ADC kernel clocks.
- Host links: USB CDC (PA11/PA12), USART serial, FDCAN1 (STM32C552 only), USB-to-CAN bridge mode.
- Kalico: GPIO, ADC with the internal temperature sensor, hardware SPI, I2C, hardware PWM, watchdog, chip ID, Katapult reboot request, reboot into the ST ROM DFU bootloader.
- Katapult: C5 flash driver, EMPTY-flag handling, 8 KiB and 16 KiB application offsets, deployer.
- Silicon errata workarounds that touch these drivers (section 5.6).
- Codex review kit, Docker build wrapper, test configs, tests, docs.

Out of scope: STM32H5 and the other C5 lines (C531/C532/C542/C562/C59x/C5A3); hard-float builds; DMA, I3C, LPUART, LPTIM, DAC, COMP, HASH, RNG, CORDIC; low-power modes; option-byte programming tools; FDCAN pins PE0/PE1 (a two-line addition later if the board needs them); upstreaming.

## 4. Key hardware facts

Every fact here is cited in the digests; the digest is the authority if this summary and a digest disagree.

- **Memory.** Flash 0x0800_0000, two banks (bank size = flash size / 2), 8 KB pages, 128-bit (quad-word) programming. SRAM1 0x2000_0000 (64 KB) and SRAM2 0x2001_0000 (64 KB) are contiguous. System memory (ROM bootloader) 0x0BF8_0000. UID 0x08FF_F800 (96 bits), flash size 0x08FF_F80C (16-bit, KB), VREFINT_CAL 0x08FF_F810, TS_CAL1 0x08FF_F814 (30 °C), TS_CAL2 0x08FF_F818 (140 °C), all calibrated at VDDA = 3.3 V. Byte reads of the 0x08FF_xxxx read-only area bus-fault. (`RM0522/ch02`, `ch06`, `ch50`, datasheet)
- **Reset state.** SYSCLK = HSIDIV3 = 48 MHz, flash at 7 wait states, all peripheral clocks off except SRAM/flash, ICACHE disabled. No PLL exists; HSI144 and PSI replace it. No voltage scaling. (`ch09`, `ch06`, `ch07`, `ch08`)
- **Flash wait states.** 144 MHz needs `LATENCY = 4` and `WRHIGHFREQ = 0b10` (Table 20). Raise wait states before raising the clock. (`ch06`)
- **PSI.** Write `PSIREFSRC`, `PSIREF`, `PSIFREQ` (RCC_CR2) only while the PSI is off. `PSIREFSRC` HSE = 00; `PSIREF` 8 MHz = 001, 16 MHz = 010, 24 MHz = 011; `PSIFREQ` 144 MHz = 01. (`ch09` Table 66 and 9.8.2)
- **Kernel clocks.** USB `CK48SEL` (RCC_CCIPR2 25:24) is disabled at reset: 01 = PSI/3, 10 = HSI/3. FDCAN, USART, SPI and I2C default to their PCLK. ADC `ADCDACSEL` = 00 (HCLK) at reset, `ADCDACPRE` 011 = /8. (`ch09`)
- **CRS.** Reset configuration already syncs to USB SOF with RELOAD = 47999; enable the CRS clock then set `AUTOTRIMEN` and `CEN`. It trims HSI144 (and therefore HSI/3). (`ch10`)
- **Boot.** Factory option bytes: `BOOT_SEL = 0` (BOOT0 pin ignored), BOOT0 option bit = 0, `BOOTADD` = 0x0800_0000. With empty flash (`FLASH_ACR.EMPTY = 1`) the chip boots the ROM bootloader, which offers USB DFU on PA11/PA12 without a crystal. `EMPTY` is not cleared by a system reset. Read protection has no level 1: setting level 2 without a provisioned OEM key is irreversible. (`ch04`, `ch06`, AN2606)
- **RAM across reset.** Factory option bytes keep SRAM1 and SRAM2 across a system reset; SRAM2 is erased on power-on. SRAM2 ECC is off at the factory. (`ch05`, `ch06`)
- **ICACHE.** Caches the code region on the C-AHB bus, including CPU data reads of flash. Cached accesses to the OTP, read-only and EDATA areas hard-fault, so those areas need a non-cacheable MPU region whenever the cache is on. (`ch06`, `ch07`)
- **Peripherals.** USB is the G0B1 `USB_DRD_FS` IP (2 KB packet memory, 32-bit access, `USB_DRD_FS_IRQn` = 62). FDCAN1 (C552 only) uses the G0/G4 fixed message RAM at 0x4000_AC00 and `FDCAN1_IT0_IRQn` = 34, AF9. SPI is the H7-style SPI v2. USART and I2C are the TIMINGR/ISR-style IPs. The ADC is a new IP closest to Kalico's H7 path; temperature sensor = ADC1 channel 12, VREFINT = ADC1 channel 13. Timers: TIM1, 2, 5, 8, 12, 15, 16, 17 (no TIM3/TIM4; TIM2/TIM5 32-bit). GPIO ports A–E and H; there is no PB11. (`ch47`, `ch46`, `ch45`, `ch43`, `ch41`, `ch21`, `ch32`, `ch11`, datasheet Table 13)

## 5. Kalico design

### 5.1 Vendor files

- `lib/stm32c5/include/`: `stm32c5xx.h`, `stm32c551xx.h`, `stm32c552xx.h`, `system_stm32c5xx.h` from `stm32c5xx-dfp` 2.1.0 (commit `a5f65bc6`), unmodified. `lib/README` records the source, version and commit like the other STM32 entries.
- The headers compile against the existing CMSIS 5 `lib/cmsis-core/core_cm33.h`. They lack the legacy `MODIFY_REG`/`SET_BIT` macros; Kalico code that needs them gets local equivalents, ST's files are not patched.

### 5.2 Build configuration

- `src/stm32/Kconfig`:
  - `MACH_STM32C551`, `MACH_STM32C552` in the processor choice, each selecting hidden `MACH_STM32C5`.
  - `MCU` strings per section 2; `CLOCK_FREQ` 144000000; `FLASH_SIZE` 0x40000; `RAM_SIZE` 0x20000; `FLASH_BOOT_ADDRESS` 0x8000000.
  - `STM32_DFU_ROM_ADDRESS` = 0x0BF80000 (to be confirmed on hardware, section 9).
  - Bootloader offset choices for C5: no bootloader, 8 KiB, 16 KiB. The default is decided by measurement in the Katapult work (section 6.4).
  - Clock reference: 8, 16, 24 MHz and internal for C5; 12/20/25 MHz hidden for C5.
  - `HAVE_STM32_USBFS` includes C5; `HAVE_STM32_FDCANBUS` includes `MACH_STM32C552` only; `MACH_STM32C5` joins the hard-PWM list.
  - Communication menus: hide options whose pins do not exist or have no matching function on C5 (USART3 PB11/PB10; CAN PB0/PB1, PC2/PC3, PD12/PD13, PH13/PH14, PI9/PH13, PA11/PA12 remap). Open UART4 PA1/PA0 to C5.
- `src/stm32/Makefile`: `dirs-` entry for `lib/stm32c5`; `CFLAGS` `-mcpu=cortex-m33 -Ilib/stm32c5/include`; `stm32/stm32c5.c` as the family file with no vendor system file; C5 selects `stm32h7_spi.c`, `stm32h7_adc.c`, `stm32f0_serial.c` and the default `stm32f0_i2c.c`, `gpio.c`, `gpioperiph.c`, `armcm_timer.c`.
- `src/stm32/internal.h`: include `stm32c5xx.h` for `MACH_STM32C5`.

### 5.3 `src/stm32/stm32c5.c` (new)

- `armcm_main`: set `SCB->VTOR`; run `dfu_reboot_check()`; reset the RCC peripheral enable registers and kernel-clock selection registers to their reset values (G0/H7 precedent: after the ROM bootloader's Go command, as used by DFU leave, peripheral registers it used may not be at reset values, AN2606 section 4.1 note on the Go command); clear `FLASH_ACR.EMPTY` if set; run `clock_setup()`; enable the instruction cache with the MPU region from 5.4; `sched_main()`.
- `clock_setup` with a crystal:
  1. Start HSE (`HSEON`, wait `HSERDY`).
  2. With the PSI off, write RCC_CR2: `PSIREFSRC = 00`, `PSIREF` for the crystal, `PSIFREQ = 01`.
  3. Set `PSISON` and `PSIDIV3ON`, wait for both ready flags.
  4. Set flash `LATENCY = 4`, `WRHIGHFREQ = 0b10`, prefetch on; read `FLASH_ACR` back.
  5. Switch SYSCLK to PSIS (`SW = 11`, wait `SWS = 11`).
  6. `CK48SEL = 01` (PSI/3) for USB.
- `clock_setup` with the internal oscillator: set `HSISON`, wait ready; flash wait states as above; `SW = 01`; `CK48SEL = 10` (HSI/3); enable the CRS clock and set `AUTOTRIMEN | CEN` when USB is the interface. CAN with the internal oscillator stays selectable, as in other families, and is documented as unsuitable.
- All AHB/APB prescalers stay /1, so `get_pclock_frequency()` returns `CLOCK_FREQ`.
- ADC kernel clock: `ADCDACSEL = 00` (HCLK), `ADCDACPRE = 011` (/8) = 18 MHz. This is inside the 8–36 MHz ADC range and lets the longest sampling time (289 cycles, 16 µs) meet the temperature sensor's 13 µs minimum.
- `lookup_clock_line()`: APB1 by offset / 0x400 with the APB1L/APB1H split at 32 (H7/G4 shape), APB2 by offset / 0x400, AHB2 GPIO ports by offset / 0x400, ADC12 special-cased to `RCC_AHB2ENR_ADC12EN`.
- `gpio_clock_enable()` through `RCC->AHB2ENR`.
- `RESERVE_PINS_crystal` = "PH0,PH1".
- `bootloader_request()`: `try_request_canboot(); dfu_reboot();`.

### 5.4 Instruction cache and the read-only area

- Kalico enables the 8 KB ICACHE after clock setup: wait until the reset invalidate has finished (`BUSYF = 0`), then set `EN`.
- Before enabling it, one ARMv8-M MPU region marks 0x08FF_E000–0x08FF_FFFF (OTP and the read-only area that holds UID, flash size and calibration values) as Normal non-cacheable, with `PRIVDEFENA` so the default map applies elsewhere. This covers the UID read at startup and the host's `temperature_mcu` calibration reads through the debug read command.
- `src/stm32/chipid.c` copies the UID into a RAM buffer with 32-bit reads before passing it to the USB serial-number and CAN UUID code, which read byte-wise. The copy applies to every family: the UID is word-aligned on all STM32 parts, so 32-bit reads are correct everywhere and no family `#if` is needed.

### 5.5 Peripheral drivers

| File | Change |
|---|---|
| `src/stm32/dfu_reboot.c` | `#if __CORTEX_M >= 7` becomes `#if __CORTEX_M == 7` (the D-cache clean exists only on M7; the current guard does not compile for M33). |
| `src/stm32/stm32f0_serial.c` | C5 joins the new-USART path with G4-style `BRR` aliases and USART1 on AF7. Options on C5: USART1 PA10/PA9 and PB7/PB6, USART2 PA3/PA2 and PD6/PD5, USART3 PD9/PD8, UART4 PA1/PA0. |
| `src/stm32/usbfs.c` | C5 uses the G0 `USB_DRD_FS` branch (32-bit packet memory) with aliases `USB_EP_CTR_RX/TX` → `USB_CHEP_VTRX/VTTX`, `USB_BASE` → `USB_DRD_FS_BASE`, IRQ `USB_DRD_FS_IRQn`. Erratum ES0661 2.12.1: wait at least 800 ns after the OUT-transfer interrupt before reading packet memory (timer-based spin in the read path). |
| `src/stm32/fdcan.c` | C5 takes the G0/G4 `RXGFC` path with AF9 and `FDCAN1_IT0_IRQn`. The pin-to-instance mapping becomes family-aware: on C5 every pin pair is FDCAN1. CAN pins on C552: PA11/PA12, PA11/PB9, PB8/PB9, PB5/PB6, PB12/PB13, PD0/PD1. PB7 is not used as TX (the datasheet lists FDCAN1_TX on both PB6 and PB7, which looks wrong). The driver leaves edge filtering (`EFBI`) off and uses only the TX FIFO, which avoids errata 2.11.1 and 2.11.2. |
| `src/stm32/stm32h7_spi.c` | Built for C5 unchanged; all five existing pin sets are valid on C5 (verified against Table 13 during implementation). |
| `src/stm32/stm32f0_i2c.c` | New C5 pin table: `i2c1_PB6_PB7`, `i2c1_PB8_PB9`, `i2c2_PB10_PB12`, `i2c2_PB3_PB4`. Erratum 2.7.2 (spurious BERR) needs no code because the driver never checks `BERR`; a comment records why. Erratum 2.7.1 (I2C kernel clock ≥ 4/10/20 MHz) is met by PCLK at 144 MHz. |
| `src/stm32/stm32h7_adc.c` | A C5 branch: no `CKMODE` write (clock comes from RCC); power-up sequence clear `DEEPPWD`, set `ADVREGEN`, wait `LDORDY`, calibrate (`ADCAL`), enable (`ADEN`, wait `ADRDY`); set the channel's `PCSEL` bit; C5 register names (`ADCC_CCR_TSEN`, `CFGR1`); preserve the reserved `CFGR1` bit 31 that resets to 1. Pins: ADC1 PA0–PA7 (IN0–7), PC0–PC3 (IN8–11); ADC2 PA0–PA3, PC4, PC5, PB0–PB2, PC1–PC3, PH4, PH5 as mapped in datasheet Table 12; temperature sensor = ADC1 channel 12 with the longest sampling time. |
| `src/stm32/hard_pwm.c` | A C5 table for TIM1, 2, 5, 8, 12, 15, 16, 17 channels from datasheet Table 13. |
| `src/stm32/watchdog.c`, `gpio.c`, `gpioperiph.c`, `src/generic/*` | No change expected; the IWDG, GPIO and DWT/SysTick timer are compatible. On this IWDG, `PR`/`RLR` writes made before the start key may not take effect, and after a ROM-bootloader Go the `PVU` bit can stay set (AN2606 4.8). `watchdog_init()` never waits on `IWDG_SR`, and the reset values (`PR` = /4, `RLR` = 0xFFF, about 512 ms) equal what it writes, so behaviour is unchanged; hardware acceptance step 9 confirms. |

| 2.11.1 FDCAN edge filtering | `EFBI` left off |

## 6. Katapult design

### 6.1 Shared code

Katapult gets the same `lib/stm32c5`, Kconfig entries, `MCU` strings, `stm32c5.c`, and C5 branches in `usbfs.c`, `fdcan.c` and `stm32f0_serial.c`, copied from Kalico with minimal drift. Like Kalico's, it resets the RCC enable and kernel-clock registers at startup, because Katapult itself is usually first started by the ROM bootloader's DFU leave. Differences from Kalico's `stm32c5.c`: no ICACHE enable and no MPU region (nothing to invalidate after flash writes), no ADC clock. The clock file goes in `mcu-y`, not `src-y`, so the deployer links (Katapult commit `287c9e1`).

### 6.2 Flash driver

A new C5 branch in `src/stm32/flash.c`, separate from the G0/G4 branch:

- Page size 8 KB. Bank size = flash size / 2, with the flash size read from 0x08FF_F80C (16-bit read). For an address: offset = address − 0x0800_0000; bank = offset / bank size, inverted when `FLASH_OPTSR_CUR.SWAP_BANK` is set; page = (offset % bank size) / 8 KB. This calculation is a pure function with a host unit test (section 8).
- Erase: clear all error flags through `FLASH_CCR`; unlock only if `FLASH_CR.LOCK` is set (keys 0x45670123, 0xCDEF89AB; a wrong or repeated key sequence bus-faults); write `PER`, `BKSEL`, `PNB`; set `STRT`; wait for `BSY` to clear.
- Program: set `PG`; write each 16-byte unit as four 32-bit writes; wait until `BSY`, `WBNE` and `DBNE` are clear; a 64-byte block is four units. Read-back verification stays as is.
- Katapult upstream issue #192: `check_erased()` scans only a quarter of its range. It gets the one-line fix as a separate commit because it affects every family.

### 6.3 Boot behaviour

- On startup Katapult clears `FLASH_ACR.EMPTY` if set, so the first reset after a ROM-DFU flash of a blank chip boots Katapult instead of the ROM bootloader.
- `RAM_SIZE` 0x20000: the request value sits in the reserved 8 bytes at the top of SRAM2, preserved across a system reset with factory option bytes. Kalico finds it through Katapult's vector table.

### 6.4 Configuration

- Application offsets 8 KiB and 16 KiB (page multiples, required by the page-erase logic). The 8 KiB deployer option includes C5.
- The default offset is measured: if every C5 Katapult build (USB, CAN, serial) fits in 8 KiB, Kalico's default C5 bootloader offset is 8 KiB, otherwise 16 KiB. Katapult's build-size guard enforces the limit.
- Test configs: C552 USB, C552 CAN, C551 serial.
- `README.md`: a short C5 section (first flash through ROM DFU with dfu-util on a blank chip; the BOOT0/`BOOT_SEL` caveat).
- `scripts/flashtool.py` needs no change.

## 7. Tooling

- **Docker.** Build `scripts/Dockerfile-build` locally as `kalico-build` with `--platform linux/amd64`; the image build runs `scripts/ci-build.sh` over every test config (CI parity) and the image runs pytest. New `scripts/docker-run.sh` runs a command in that image with the current directory mounted; Katapult builds use it from `~/Code/katapult`.
- **Codex review kit.** Copy from `~/Code/HART-CETEC-Admin-Tool`: `scripts/codex-review.sh`, `.claude/agents/codex-reviewer.md`, `.claude/rules/adversarial-review.md`. Committed in Kalico. Adapt the rule file for firmware: security covers memory safety, interrupt races and anything that can brick a chip (option bytes, flash writes outside the application area, read protection); usability covers Kconfig menus, error messages and docs; remove UI-only references. In Katapult the kit is local-only (listed in `.git/info/exclude`) so that branch holds only C5 work.
- **Review cadence.** Codex review per plan task, then a whole-branch review per repo.

## 8. Testing

Every item is written red first (TDD).

1. **Kconfig unit test.** `test/test_kconfig_defconfig_roundtrip.py` asserts that every symbol in each test config exists on first load (kconfiglib silently drops unknown symbols, so a C5 config would otherwise build a default MCU). New `test/configs/` files for C551 and C552 (USB, CAN, serial variants) fail until the Kconfig work lands.
2. **Build tests.** Every C5 config builds without warnings in Docker in both repos; all existing configs still build.
3. **Klippy integration test.** A `test/klippy/printers.test` entry with the real `stm32c552.dict` and a printer config using C5 ADC pins, the MCU temperature sensor, PWM pins, SPI and I2C bus names and CAN, so the firmware's enumerations are checked against what the host expects.
4. **Python unit tests.** The `flash_usb.py` C5 mapping and the `temperature_mcu` C5 calibration path through their real code.
5. **C unit test.** Katapult's address-to-bank/page function (including `SWAP_BANK`) as a host-compiled test with a small script, run in Docker.
6. **Hardware end-to-end.** The acceptance checklist in section 9, run on Erik's board as follow-up work.

C register-level code (clock setup, drivers) has no unit tests: neither repo has a C unit-test harness, so it is covered by the build, integration and hardware tests. Erik approved this testing plan on 2026-10-01.

## 9. Hardware acceptance (follow-up, Erik's board)

1. Dump the first two words at 0x0BF8_0000 with the J-Link: expect SP = 0x2000_xxxx and an odd PC in 0x0BF8_xxxx. Correct `STM32_DFU_ROM_ADDRESS` if not.
2. Blank chip: flash Katapult through ROM DFU (`dfu-util`). Reset: Katapult runs (EMPTY cleared), not the ROM bootloader.
3. Flash Kalico through Katapult over USB, and over CAN.
4. Klippy connects over USB, over UART and over CAN; USB-to-CAN bridge mode works.
5. `temperature_mcu` reads a plausible temperature; an ADC thermistor reads sanely.
6. Hardware PWM output measured; a TMC driver over SPI and over UART responds; an I2C sensor responds.
7. Kalico → Katapult reboot request (`flashtool.py -r`) and Katapult double-reset entry work.
8. `make flash` reboots into ROM DFU and flashes Kalico (`STM32_DFU_ROM_ADDRESS` path).
9. Watchdog reset recovers a hung MCU.
10. Step-rate benchmark recorded in `docs/Features.md` / `docs/Benchmarks.md`.

## 10. Risks and open items

| Item | Mitigation |
|---|---|
| ROM DFU entry vector at 0x0BF8_0000 unverified | J-Link check (section 9, step 1) before relying on `make flash` |
| DWT `CYCCNT` behaviour across `WFI` on this M33 unverified | RP2350 (M33) uses the same timer; checked in hardware acceptance (timing works under load) |
| Datasheet lists `FDCAN1_TX` on PB6 and PB7 | No Kconfig option uses PB7 for CAN |
| HSI144 runs slightly fast (144.07–145.08 MHz at 30 °C) | Crystal recommended; with USB, CRS trims HSI144 |
| Katapult size with USB/CAN may exceed 8 KiB | Measured during implementation; default offset follows (section 6.4) |
| Option-byte changes (SRAM erase on reset, SRAM2 ECC, `BOOT_LOCK`, read protection) can break boot handshakes or lock the chip | Firmware never writes option bytes; docs warn |
| PDFs came from a GitHub mirror (st.com unreachable) | Newer revisions may exist; re-check RM0522/ES0661 revisions before hardware bring-up |
